# Security

Keyfit decides which credentials `claude`, `codex`, `opencode`, `copilot`, `aws`, `gh`, `vercel`, `supabase`, `wrangler` and `convex` get. This page says what it can see, what it keeps and where, what it sends and to whom, and what it does not protect against. To report a problem, see [the end of this page](#reporting-a-problem); please don't open a public issue.

## In short

- **What it is for:** stopping a tool from using the wrong project's account by accident. It is not a sandbox and not a secrets vault, and it does not protect you from code that already runs as you.
- **No secret values in Keyfit's files.** Keys you paste into Keyfit go into the macOS Keychain.
- **A key or token leaves your Mac only for its own service**, over HTTPS, when Keyfit asks that service whose it is.
- **No telemetry, no update checks, no log files, no writes into your repositories.**
- **Keyfit's output never shows a key or token.**

## What Keyfit can see

Keyfit runs as you, so it could read anything you can. This is what it actually reads:

| What | Why |
|---|---|
| `~/.config/keyfit/registry.toml` and `cache/checks.json` | your projects, and recent successful checks |
| The environment of the shell that starts the tool | to clean it up; an `env:NAME` reference reads the key from `$NAME` |
| Keychain items named by `keychain:service/account` references | the key, read with `/usr/bin/security find-generic-password -w` only when a launch or check needs it |
| `~/.aws/config`, `~/.aws/credentials`, `~/.aws/sso/cache`, `~/.aws/login/cache` | the profile's type and account hints, whether it has a static key, sign-in expiry times. Keyfit never uses or sends the AWS tokens in these files |
| gh's token for the mapped account (`gh auth token --user LOGIN`), for the GitHub account and the Copilot CLI account | to hand it to the tool as `GH_TOKEN` (as `COPILOT_GITHUB_TOKEN` for Copilot CLI) and ask GitHub whose it is |
| The Vercel login folder's `auth.json` and `config.json` | the token, to ask Vercel whose it is, and the selected team |
| The supabase CLI's login, on `keyfit add supabase --cli` and on a yes in `keyfit init` only | whether it is signed in, from the attributes of the Keychain items `Supabase CLI/supabase` and `Supabase CLI/access-token` (no secret is read for that), or from `~/.supabase/access-token`; then, to copy it, the token. Newer CLIs store it through a native module, so macOS may ask you once to let `security` read it. It is never read at a launch |
| wrangler's config folder (`~/Library/Preferences/.wrangler`, or `~/.wrangler` when it exists) | the names of the files in `config/` (which profiles exist; the files themselves, wrangler's sign-ins, are never opened, only their modification time and size for the cache), and `profiles/directory-bindings.json` (which folder is bound to which profile) |
| `~/.convex/config.json`, the convex CLI's login, for an account that is that login (at every launch of `claude`, `codex`, `opencode`, `copilot` or `convex` in its project), on `keyfit add convex --cli` or `--copy`, and to see whether it is signed in during `keyfit init` | the token, to hand it to the session and ask Convex which teams it sees. A plain file the CLI writes; reading it asks nothing |
| OpenCode's database of the project's account (`~/.local/share/opencode/opencode.db`, or the account's `opencode.db`), read-only with SQLite | the provider, label and ID of each sign-in (`SELECT id, integration_id, label, active FROM credential`). The column holding the credential is never read |
| OpenCode's `opencode.json` and `opencode.jsonc` in `~/.config/opencode` (or `$OPENCODE_CONFIG_DIR`), the file `$OPENCODE_CONFIG` names, and `$OPENCODE_CONFIG_CONTENT` | MCP server names and the variable each one reads, to hide other projects' servers |
| Copilot CLI's `mcp-config.json` in `~/.copilot` (or `$COPILOT_HOME`, or the folder `copilot --config-dir` names), and the JSON or file `copilot --additional-mcp-config` names | MCP server names and the variable each one reads, to hide other projects' servers. Copilot's login and settings are never read |
| `~/.claude.json` (or the account's), Claude's `settings.json`, `~/.codex/auth.json`, `~/.codex/config.toml` | MCP server lists, organization and account IDs, the login type, whether you set your own status line. Codex tokens are never used or sent |
| In the project folder: `.mcp.json`, `opencode.json` and `.opencode/opencode.json` (also in the folders above it), `.github/mcp.json` (for Copilot CLI, with `.mcp.json`, also in the folders above it up to the repository's top), `.vercel/project.json` and `repo.json`, `supabase/.temp/project-ref` (in the nearest folder upwards with `supabase/config.toml`), the `wrangler.json`, `wrangler.jsonc` or `wrangler.toml` wrangler would read, the `package.json` of the wrangler `npx` would run, the `CONVEX_*` lines of `.env.local` and `.env` (and of a file named with `convex --env-file`), the git config | server names to hide, the Vercel team and Supabase project the folder is linked to, the Cloudflare `account_id`, wrangler's version, the Convex deployment the folder points at, the author email and origin host. Other lines of `.env.local` are read with the file but never kept or used |
| `.envrc` of the repository, on `keyfit init` only | `use aws` and `export LINEAR_API_KEY=$VAR` lines. It is read as text and never run |
| `PATH` | to find the real tool behind each shim |

Programs Keyfit runs, all read-only: `git rev-parse`, `git config user.email` and `git remote get-url origin`; `aws sts get-caller-identity`; `claude auth status --json`; `opencode auth list --standalone --format json` (in an empty temporary folder that is also its configuration folder, with the project's configuration, the model list and the update check off, so no MCP server or plugin starts; it opens the account's database, as OpenCode does at a start); `gh auth token` and `gh auth status`; `vercel whoami` (only to let the CLI renew an expired token); `wrangler whoami --json` (wrangler renews an expired sign-in first, as every wrangler command does); `wrangler auth token --json --profile NAME` on `keyfit add cloudflare` only, to list the accounts the profile reaches; `/usr/bin/security`. Apart from `security` and `wrangler`, each is the first one found on PATH (skipping Keyfit's shims and Superset's wrappers), and runs in the current folder, as the tool itself will. `wrangler` is the one `npx wrangler` would run there: the nearest `node_modules/.bin/wrangler` (up to your home folder), else the one on PATH. So a registered project's own wrangler runs at its check, as it would at its next deploy.

## What Keyfit stores, and where

Everything lives under `~/.config/keyfit` (or `$KEYFIT_CONFIG_DIR`), apart from Keychain items and one optional line in a shell startup file.

| Path | Mode | Contents |
|---|---|---|
| `registry.toml` | 600 | Projects, their folders and account labels: AWS profile names and 12-digit account IDs, Linear workspace slugs, where each key lives (`env:NAME` or `keychain:service/account`), GitHub logins, Vercel users and teams, Supabase organization slugs and names, wrangler profile names and Cloudflare account IDs and names, Convex team slugs and names (and `token = "cli"` for an account that is the convex CLI's own login), Claude organizations, Codex plans (plus the email or account ID when you pin one), the GitHub login Copilot CLI runs as, the path of each OpenCode database and the providers signed in there, MCP server name patterns, and the names of Keychain items Keyfit stored. Never a key, token or password |
| `cache/` and `cache/checks.json` | 700, 600 | Successful online checks: time, status and a short label such as `account confirmed`, under a SHA-256 of the project, the connection and a login fingerprint. For Linear, GitHub (also Copilot CLI's) and Vercel the fingerprint is the first 16 hex characters of a SHA-256 of the key or token; for Supabase, of the token and the linked project; for Cloudflare, of the modification time and size of the profile's sign-in file (never its content); for Convex, of the token and the deployment the folder points at; for OpenCode, of the IDs, providers and labels of the database's sign-ins and the names (never the values) of variables ending in `_API_KEY` or `_TOKEN`. Supabase projects named on a command line (`--project-ref`) and Convex deployments (`--deployment-name`) confirmed to belong to the project's organization or team are kept the same way |
| `bin/` (the shims), `shell.zsh`, `shell.sh` | 755, 644 | Two-line `sh` scripts and the PATH snippets. Nothing secret |
| `claude/NAME/` | 700 | Only after `keyfit add claude --new`: a config folder for another Claude login, where Claude keeps that login's history and transcripts. Its `.claude.json` (600) marks the project's folders as trusted only where your default Claude login already trusts them, so a new login never trusts more than the old one |
| `vercel/NAME/` | 700 | Only after `keyfit add vercel --new`: the Vercel CLI keeps that login's `auth.json` here |
| `opencode/NAME/` | 700 | Only after `keyfit add opencode --new`: OpenCode keeps that account's database here, with its sign-ins and sessions |
| macOS Keychain, service `keyfit` | Keychain | Keys you pasted into `keyfit add linear` (`linear-WORKSPACE`), `keyfit add supabase` (`supabase-NAME`, also the copy `--cli` makes of the supabase CLI's token), `keyfit add convex` (`convex-NAME`, also the copy `--copy` makes of the convex CLI's token) or `keyfit secret set NAME`. They are written through the stdin of `security -i`, never through its arguments |
| Your shell startup file | | One line that loads `shell.zsh` or `shell.sh`, only with `keyfit setup --rc` |

`~/.config/keyfit` itself gets your usual permissions (usually 755). The registry, the cache and Claude's `.claude.json` are owner-only from the first byte. `keyfit setup --remove --purge` deletes the folder but never Keychain items; it lists their names so you can delete them in Keychain Access.

## What Keyfit sends, and to whom

Nothing in folders that aren't registered. In a project, Keyfit only asks each service who you are:

| To | What | When |
|---|---|---|
| `api.linear.app` (`POST /graphql`) | the project's Linear key and the query `{ organization { urlKey name } }` | a Linear check without a fresh cached success, `keyfit status`, `keyfit add linear`, `keyfit init` importing a key from `.envrc`. Only a value shaped like a Linear key is ever sent |
| `api.github.com/user` | gh's token for the account | a GitHub or Copilot CLI check without a fresh cached success, `keyfit status`, `keyfit add github`, `keyfit add copilot`. A classic personal access token is never sent for Copilot CLI: it fails before |
| `api.vercel.com` (`/v2/user`, `/v2/teams/…`) | the login's token from `auth.json` | a Vercel check without a fresh cached success, `keyfit status`, `keyfit add vercel`, guided `keyfit init` |
| `api.supabase.com` (`GET /v1/organizations`, `GET /v1/projects/REF`) | the project's Supabase token | a Supabase check without a fresh cached success (`/v1/projects/REF` only when the folder is linked), `keyfit status`, `keyfit add supabase`; `/v1/projects/REF` also when a `supabase` command names another project (`--project-ref`, `link REF`, …). Only a value shaped like a Supabase token is ever sent. Never a call that returns keys or database passwords |
| AWS STS, through the real `aws` | whatever `aws sts get-caller-identity --profile P` sends | an AWS check without a fresh cached success, `keyfit status`, `keyfit add aws` when the profile doesn't name its account |
| `api.cloudflare.com` (`GET /client/v4/accounts`) | the token of the wrangler profile you pick | `keyfit add cloudflare` only, to list the accounts the profile reaches. The token comes from `wrangler auth token` and is held in memory for that one request |
| Cloudflare, through the real `wrangler` | whatever `wrangler whoami` sends (and, when the sign-in has expired, wrangler's own renewal) | a Cloudflare check without a fresh cached success, `keyfit status` |
| `api.convex.dev` (`GET /api/teams`, `GET /api/deployment/NAME/team_and_project`) | the project's Convex token | a Convex check without a fresh cached success (the deployment only when the folder points at a cloud deployment), `keyfit status`, `keyfit add convex`; the deployment also when a `convex` command names another one (`--deployment-name`, `--env-file`, …). These are the calls `npx convex login status` and the CLI's deployment lookup make. A deploy key is never sent, and a value shaped like one is never sent as a token |
| Anthropic, through the real `claude` | whatever `claude auth status` sends | a Claude check without a fresh cached success, `keyfit status`, `keyfit add claude` |
| Nothing, through the real `opencode` | `opencode auth list` asks no provider. Keyfit turns off its model list, update check and configuration, and it then needs no network (verified with OpenCode 2.0.25 and every outbound connection but localhost blocked) | an OpenCode check without a fresh cached success, `keyfit status` |
| Vercel, through the real `vercel` | whatever `vercel whoami` sends to renew its token | only when the stored Vercel token has expired |

Keyfit's own requests use HTTPS with certificate and hostname checks (Python's default; when Python has no CA certificates of its own, Keyfit uses the bundle macOS keeps at `/etc/ssl/cert.pem`). They never follow a redirect, because a redirect would carry the key to another address. Each has a 15 s timeout. Like other tools, they honor `HTTPS_PROXY` and `SSL_CERT_FILE` from your environment. Codex is checked offline, from `auth.json`, and OpenCode from its own database and `opencode auth list`.

**The cache.** A successful online check is reused for 30 minutes. If a service can't be reached (a connection error, a DNS failure or a timeout; for Vercel, Supabase and Convex also a rate limit or server error), Keyfit retries once. If that also fails, it accepts a success from the last 24 hours for the same login and shows it as a warning. A rejected key, an expired sign-in or a wrong account always fails, and failures are never cached. AWS profiles that aren't SSO or console sign-ins (`credential_process`, static keys, roles) have no login fingerprint: a credential swapped behind the same profile name is noticed when the 30 minutes run out, or at once with `keyfit status`.

## What Keyfit never does

- **Print a key or token.** Output names the variable or the Keychain item, and shows AWS account IDs as their last four digits. `KEYFIT_DRY_RUN=1` lists the names of changed variables only. An internal error shows the exception's type and place, not its message, since messages can quote the file that was read. A key typed where a name or reference belongs (`--key lin_api_…`) is refused without being repeated.
- **Put a secret on a command line**, where `ps` would show it to every process.
- **Send a secret anywhere but its own service** (the table above).
- **Collect telemetry or keep logs.** No analytics, update checks or crash reports.
- **Write into your repositories, or change another tool's logins or configuration.** It never runs `gh auth login`, `gh auth switch` or `copilot login`. It runs `aws login`, `aws sso login`, `claude auth login`, `codex login`, `opencode auth login --standalone`, `vercel login`, `wrangler auth create NAME`, `wrangler login` or `npx convex login --force` only when you answer yes to `Sign in now?`, which it asks only when you start a tool yourself in a terminal and every failed check is fixed by such a sign-in; the sign-in then talks to you directly, and the checks run again before the tool starts. Otherwise it prints them as the fix. The other exceptions are `vercel whoami` and `wrangler whoami`, which renew an expired token, as any `vercel` or `wrangler` command would, and `wrangler auth activate NAME DIR`, which binds a folder to a wrangler profile (it changes only wrangler's list of bound folders, no sign-in). `keyfit add cloudflare` runs it only when you answer yes to `Run it now?`, and a shim only when you answer yes to `Bind this folder now?`, which it asks only when you start a tool yourself in a terminal, every failed check is fixed by a sign-in or by that binding, NAME is the project's own profile and DIR is a folder of the project (never another project's, never your home folder or a folder above it; in a Superset worktree, the folder that holds the repository's worktrees when nothing in it belongs to another project).
- **Start a tool after a failed check, a mistake in the registry (`registry.toml has a mistake`), an error inside Keyfit, or from a shim whose Keyfit installation is gone.** The exceptions are `KEYFIT_DISABLE=1`, sign-in commands (they run with the project's environment but without checks), folders that aren't registered, the AWS profiles under `[settings] shared_aws_profiles`, and a network failure within 24 hours of a success, shown as a warning.

## Where secrets end up

`claude` and `codex` start with the project's Linear key (as `LINEAR_API_KEY`, and in the project's own `env:` variable), gh's token for the project's GitHub account (as `GH_TOKEN`; that is gh's own login token, with all of its scopes), the project's Supabase token (as `SUPABASE_ACCESS_TOKEN`, with `SUPABASE_PROFILE=supabase`, so a profile file in a folder cannot send it to another API host) and the project's Convex token (as `CONVEX_OVERRIDE_ACCESS_TOKEN`, without `CONVEX_PROVISION_HOST`, which would send it to another API host). Inside a session Keyfit started, a `gh` call keeps the session's `GH_TOKEN` instead of asking gh again only when the project's check confirmed exactly that token in the last 30 minutes and gh's sign-ins (the time of `hosts.yml`, never its content) haven't changed since. `claude` and `codex` also get the project's Cloudflare account as `CLOUDFLARE_ACCOUNT_ID` (an ID, not a secret), and lose inherited `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_API_KEY` and `CLOUDFLARE_EMAIL` (and their `CF_` names), which would beat wrangler's sign-in for the folder. `opencode` and `copilot` get the same as `claude` and `codex`. In a project with a Copilot CLI account, all four also get gh's token for that account as `COPILOT_GITHUB_TOKEN` (Copilot CLI takes it before `GH_TOKEN`, `GITHUB_TOKEN`, its own login and gh's; inside a session Keyfit started it is kept on the same terms as `GH_TOKEN`), and lose inherited `COPILOT_GITHUB_TOKEN`, the Copilot coding agent's `GITHUB_COPILOT_…_TOKEN` variables, `COPILOT_GH_HOST` and `GH_HOST` (another GitHub host) and the `COPILOT_PROVIDER_…` variables (a model provider and its key instead of the GitHub account), which only Copilot reads. In a project with an OpenCode account, all four also get `OPENCODE_DB` (the account's database), and `opencode` starts without inherited `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`, `GOOGLE_API_KEY`, `GITHUB_TOKEN` and `OPENCODE_API_KEY`, which OpenCode would take as sign-ins next to the database's. An OpenCode session runs on a private server (`--standalone`), so the commands it runs have this environment and no other start's. OpenCode's shared background server is never started with a project's environment: its own commands (`mcp`, `serve`, `service` and the like) run with yours, unchanged, from your terminal, and inside a session Keyfit started (where the environment holds a project's accounts) they get `--standalone` where they take it and are refused otherwise; so is an `opencode` in a folder outside every project, started from such a session. `aws`, `gh`, `vercel`, `supabase`, `wrangler` and `convex` get only their own account. Everything the tool starts inherits its environment: MCP servers, hooks, the commands an agent runs, and the install scripts of the packages it installs. Keyfit removes other projects' variables only for the kinds of account the project maps, with five exceptions: a Supabase or Convex token Keyfit gave another project's session (marked by `KEYFIT_SUPABASE` or `KEYFIT_CONVEX`) is removed in a project without such an account, and so are the `CLOUDFLARE_ACCOUNT_ID` Keyfit set (marked by `KEYFIT_CLOUDFLARE`) in a project without a Cloudflare account, the `OPENCODE_DB` it set (marked by `KEYFIT_OPENCODE`) in a project without an OpenCode account, and the `COPILOT_GITHUB_TOKEN` it set (marked by `KEYFIT_COPILOT_LOGIN`) in a project without a Copilot CLI account. In a project with a Convex account, inherited `CONVEX_DEPLOYMENT`, `CONVEX_DEPLOY_KEY` and `CONVEX_DEPLOYMENT_TOKEN` that the folder's own `.env.local` or `.env` disagree with are removed too: they would outrank the folder's files. In folders that aren't registered, the tool gets your environment unchanged, apart from `KEYFIT_SHIM_DEPTH`, a counter that stops shims from calling each other in a loop.

## What Keyfit does not protect against

- **Code that already runs as you.** It can read the same files and environment, call the real binaries by full path, set `KEYFIT_DISABLE=1`, edit the registry or remove the shims. It can also read the Keychain items Keyfit stored, without a prompt, through `/usr/bin/security`; that is how Keyfit reads them without asking at every launch. The Keychain protects them at rest and from other users, not from your own processes.
- **An agent that goes around the ten commands:** one that reads `~/.aws`, gh's or Vercel's stored logins or the Keychain directly, or runs a tool by its full path. Keyfit only decides what `claude`, `codex`, `opencode`, `copilot`, `aws`, `gh`, `vercel`, `supabase`, `wrangler` and `convex` get when they are started through PATH. Other programs (`vc`, `npx supabase`, `npx wrangler`, `npx convex`, `npx @github/copilot`, terraform, npm, IDE extensions, desktop apps) don't go through Keyfit; inside a Claude, Codex, OpenCode or Copilot CLI session, `npx supabase`, `npx convex` and `npx @github/copilot` do get the project's token and `npx wrangler` the project's account, but none of the shim's refusals (`--project-ref` of another organization, `--deployment-name` of another team, `--profile`, `--admin-key`). An agent that `cd`s into another Convex folder and runs `npx convex` there still acts with its own project's token, on the deployment that folder's `.env.local` names. wrangler itself also loads `CLOUDFLARE_API_TOKEN` from the folder's `.env`, which beats the profile; the pinned account still holds.
- **What a tool does with the right account.** An agent with the project's AWS profile can do whatever that profile allows. Give each project's profile only the permissions it needs.
- **Configuration a repository brings with it, once you trust it.** After you trust a folder in Claude, its `.claude/settings.json` applies to the agent's commands, and its `env` can set `KEYFIT_DISABLE`, `KEYFIT_PROJECT` or `AWS_PROFILE`. An `.envrc` you `direnv allow` can do the same. Keyfit can't tell those from your own settings. A project `.mcp.json` server you approve gets the session's environment, or any variable it names, such as `${LINEAR_API_KEY}` or `${GH_TOKEN}`. `keyfit init` imports the repository's `.envrc` lines, so register only repositories you trust and read the `imported …` lines it prints.
- **`KEYFIT_DISABLE=1` beyond the one command.** It is inherited: an agent started with it runs its own `aws`, `gh`, `vercel`, `supabase`, `wrangler` and `convex` without Keyfit too.
- **What is on PATH.** Keyfit runs the first `aws`, `claude`, `codex`, `opencode`, `copilot`, `gh`, `vercel`, `supabase`, `wrangler`, `convex`, `npx` (for `Sign in now?` on a Convex login) and `git` on PATH after its shims and Superset's wrappers, as your shell would (for its Cloudflare check, the project's own `node_modules/.bin/wrangler` first, as `npx` would). A compromised binary or a malicious folder early on PATH wins. That includes relative entries such as `.` or `./node_modules/.bin`, which point into whatever folder you are in.
- **MCP servers Keyfit doesn't see.** It hides servers by name from `~/.claude.json` (user scope), the current folder's `.mcp.json`, `~/.codex/config.toml`, OpenCode's configuration files and Copilot CLI's (see above). Servers of installed Copilot CLI plugins are not hidden; its built-in GitHub server runs as the project's account. OpenCode servers that come with a provider's well-known configuration (an organization's sign-in) are not hidden. Servers from plugins, claude.ai connectors or Claude's local scope are not hidden, and Keyfit doesn't vet any server. Codex can't hide a server whose name has a dot or `=`, so if such a server must be hidden, `codex` doesn't start until you rename it.
- **Accounts you didn't map, and identities it can't confirm online.** Unmapped accounts are neither checked nor cleaned up: in a project without a Supabase or Convex account, `supabase` and `convex` run with the CLI's own login, as before Keyfit. A Supabase token is checked by organization, not by person; a folder linked to a preview branch is not checked (a warning says so); and `--db-url` connects to a database with its password, without the account. A Convex login is checked by team, not by Convex project; project deploy keys, local and self-hosted deployments are not checked. Codex is checked from its local `auth.json` only, and Claude from what `claude auth status` reports. Copilot CLI is checked by GitHub login: whether that account has a Copilot plan is not checked (Copilot CLI says so when it starts). OpenCode is checked by provider: its sign-ins carry the provider's name, not the person's, so a sign-in to another person's account of the same provider in the project's database is not noticed, and no provider is asked whether a sign-in still works. Cloudflare is checked by account: which wrangler profile a folder uses is read from wrangler's bindings file, as wrangler reads it, and wrangler 4.106 or newer is needed (older ones ignore profiles).

## How to audit it

- `KEYFIT_DRY_RUN=1 claude` in a project runs the checks and prints the real binary, the arguments Keyfit adds (including the `--settings` JSON with the hidden MCP servers) and the names of the variables it changes. It starts nothing.
- `keyfit which -v` shows which project a folder belongs to, and why. `keyfit status` runs every check online.
- `cat ~/.config/keyfit/registry.toml`, `cat ~/.config/keyfit/cache/checks.json` and `cat ~/.config/keyfit/bin/claude` show plain files with nothing secret in them.
- `keyfit secret list`, or Keychain Access (search for "keyfit"), shows the items Keyfit stored.
- The code uses Python's standard library only. A launch goes through `keyfit/shim.py` (the launch), `resolve.py` (which project), `environment.py` and `adapters/` (injecting and checking), `mcp.py` (hiding MCP servers), `secrets.py` (Keychain and `env:` references), `http.py` (TLS) and `cache.py`.

## Reporting a problem

Please don't report a vulnerability in a public issue, pull request or discussion. Report it privately instead:

- on GitHub, with private vulnerability reporting: the repository's **Security** tab, then **Report a vulnerability** (<https://github.com/FlamurMaliqi/keyfit/security/advisories/new>), or
- by email to <contact@flamur-maliqi.de>.

[SECURITY.md](../SECURITY.md) says what to include and what counts. Never send real keys or tokens, not even expired ones.
