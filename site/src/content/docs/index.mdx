## For people who work for several clients

<p class="kf-lead">
	Coding agents run <code>aws</code>, <code>gh</code> and MCP tools on their own. When each client has its own AWS
	account, Linear workspace and GitHub login, one leftover environment variable is enough for an agent to act as the
	wrong client. Tools that switch credentials per folder assume the switch worked. Keyfit asks each service who you
	are signed in as, and stops the tool if the answer is wrong.
</p>

## How it works

<Steps>

1. **It recognises the project.** From the folder you are in, including every git worktree of a registered repository (Superset's too). Folders you haven't registered work exactly as before.

2. **It checks every account with the service.** AWS, Linear, GitHub and Claude are asked who you are. Expired sign-ins are caught before anything runs. Successful checks are reused for 30 minutes, so launches stay fast.

3. **It starts the tool with only that project's credentials.** Conflicting keys inherited from your shell are removed, and MCP servers that belong to other projects are hidden. If a check fails, the tool does not start and you see the command that fixes it.

</Steps>

## What it checks

<CardGrid>
	<Card title="AWS" icon="cloud-download">
		The account behind the profile, via <code>sts get-caller-identity</code>. Inside a project, <code>aws --profile</code> with another project's profile is refused.
	</Card>
	<Card title="Linear" icon="list-format">
		The workspace behind the API key. Keys you add are stored in the macOS Keychain, never in a file.
	</Card>
	<Card title="GitHub" icon="github">
		The login behind <code>gh</code>'s token for that account, checked with GitHub.
	</Card>
	<Card title="Claude Code" icon="comment">
		The organization of the claude.ai login. Login pools that rotate between accounts keep working.
	</Card>
	<Card title="Codex" icon="rocket">
		A ChatGPT login without an API key, so a stray key never takes over.
	</Card>
	<Card title="MCP servers" icon="puzzle">
		Each project sees its own Linear server. Servers you assign to a project stay out of every other one.
	</Card>
</CardGrid>

## Install

You need macOS, Python 3.11 or newer, and zsh or bash.

<Tabs syncKey="install">
	<TabItem label="Homebrew">
		```bash
		brew install flamurmaliqi/keyfit/keyfit
		```
	</TabItem>
	<TabItem label="pipx">
		```bash
		pipx install keyfit
		```
	</TabItem>
</Tabs>

Then, once:

```bash
keyfit setup --rc   # puts Keyfit in front of claude, codex, aws and gh (new terminals)
cd ~/code/acme-api
keyfit init         # registers the repository and offers the accounts it finds on your Mac
```

## Private by design

<CardGrid>
	<Card title="Runs on your Mac" icon="laptop">
		No account, no server, no telemetry. It is a small command-line tool with no dependencies.
	</Card>
	<Card title="Keys stay secret" icon="approve-check">
		Never printed, logged or written to Keyfit's files. Keys you add live in the macOS Keychain.
	</Card>
	<Card title="Talks only to the services it checks" icon="random">
		AWS, Linear, GitHub and Claude, to ask who you are. Each key goes only to the service it belongs to.
	</Card>
	<Card title="Leaves your repositories alone" icon="document">
		It never writes into your code and never changes another tool's login.
	</Card>
</CardGrid>

## Questions

<div class="kf-faq">

<details>
<summary>Does it slow my tools down?</summary>

Barely. Local checks run on every launch; the online checks are reused for 30 minutes, so most launches add a fraction of a second. The first check after a break takes a second or two.

</details>

<details>
<summary>What happens in folders I haven't registered?</summary>

Nothing. The tools run exactly as before Keyfit.

</details>

<details>
<summary>I already use direnv. Do I need to retype everything?</summary>

No. `keyfit init` imports `use aws PROFILE ACCOUNT_ID` and `export LINEAR_API_KEY=$VARIABLE` lines from the repository's `.envrc`. It reads the file as text and never runs it.

</details>

<details>
<summary>Does Keyfit see my code or my prompts?</summary>

No. It only decides which accounts a tool starts with, then hands over to the real tool.

</details>

<details>
<summary>Does it work on Linux or Windows?</summary>

Not yet. Keys live in the macOS Keychain, so the first version is macOS only. Linux is planned.

</details>

<details>
<summary>How do I skip or remove it?</summary>

`KEYFIT_DISABLE=1 claude` skips Keyfit once. `keyfit setup --remove` takes it out of your shell; your projects stay registered until you add `--purge`.

</details>

<details>
<summary>What does it cost?</summary>

Nothing. Keyfit is open source under the MIT licence.

</details>

</div>
